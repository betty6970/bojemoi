### Description

Qwen 2.5 Coder generates tool calls as text JSON {"name":..,"arguments":..}
instead of OpenAI-compatible tool_calls array. norma SDK requires native
tool_calls to continue the agent loop — causing workers to end after 1 turn
with 0 facts/findings.

Fix: lightweight FastAPI proxy (artex-tool-proxy) between ARTEX and Ollama:
- Converts text tool calls and <tool_call> XML to native tool_calls format
- Handles mixed content (planning text + JSON tool call)
- Auto-nudge retry (MAX_RETRIES=2) when model returns preamble text before
  calling a tool: injects assistant context + user nudge, re-queries Ollama
- Forces non-streaming (stream=false) for deterministic response analysis
- Pass-through for all other Ollama API endpoints (api/tags, api/show, etc.)

Workers now complete 8+ turns with real Bash/record_coverage/add_intent
tool calls instead of ending after 1 text turn.
