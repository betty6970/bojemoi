### Description

Root cause : _set_status() recevait une conn pré-acquise AVANT await _run_sync().
Avec 88 attaques simultanées et le threadpool saturé (kali/nuclei ~60-120s),
les coroutines se suspendaient en gardant leur connexion ouverte → 20+ connexions
simultanées → PoolError.

Fix : wrapper _update_status() ouvre sa propre connexion seulement quand le
worker threadpool tourne (conn lifetime = SQL time, pas wait time + SQL time).
Pattern identique à toutes les autres méthodes DB du fichier (_set_phase, etc.)
